## 0. 一页结论

| 决策项 | 选定方案 | 一句话理由 |
|---|---|---|
| 技术栈 | **微信原生小程序**（不上 Taro/uni-app） | 只有微信一端，原生包体最小、Canvas 与分享能力最直接、审核问题最少 |
| 后端 | **微信云开发**（云函数 + 云数据库 + 云存储） | 个人主体可开通；**免服务器、免域名、免域名备案、免配置请求域名白名单** |
| 内容 | **不搬 HTML，搬数据**（Content JSON） | 1 套数据驱动页面覆盖 15 位科学家，包体积与科学家数量解耦 |
| 图片 | **34.7MB 全部上云存储**，包内零原图 | 主包/单分包硬上限 2MB，原图进包必爆 |
| 账号 | **静默登录**（openid 即账号），不弹授权框 | 个人主体拿不到手机号，也不需要——静默登录最合规最顺审 |
| 类目 | **工具 > 信息查询**（单一类目，**不加教育**） | 成长计划要求「类目**仅含**文娱/工具/社交/深度合成/资讯」，加教育会丢掉 6 个月免费云环境；术语检索本身就是"信息查询"的功能支撑 |
| 第一版不做 | 实物支付 / 视频 / AI 问答 / 公开评论 / 排行榜 / 任何 UGC | 踩个人主体红线，见第 1 节（**虚拟支付可做**，见 §1.1） |
| 预算 | 认证 **30 元/年** ＋ 云开发 **≈19.9 元/月** | 免费云环境在**上线后第 15 天**到期，必须预留 |

**最长路径不是开发，是备案。** 备案 1–20 个工作日且不可压缩 → **今天就要提交**。

## 0.5 v1 落地状态与三处实测修正

已落地：内容抽取器、工程骨架、门户（**查询优先**）/ 词典 / 科学家档案 / 我的 四页、
术语弹层组件、两个云函数（`login` / `report`）、tabBar PNG 图标、静态校验器与护栏自证脚本。
校验结果：`python3 tools/validate_miniapp.py` → **24 项通过 / 0 错误 / 0 警告**，主包 **596 KB**。
护栏自证：`python3 tools/selftest_miniapp_guardrails.py` → 对每条护栏注入人造错误，确认拦得住
（「全过」只证明工程干净，不证明护栏有效——这个区别本项目付过一次学费，见下方修正表后的注）。

动手后发现三处与最初估算不同，以实测为准：

| 项 | 原估算 | 实测 | 结论 |
|---|---|---|---|
| 内容层体积 | ≈1 MB | **292 KB**（roster 9.6 + terms 282） | 比预想宽裕得多，v1 整包放主包；分包是"以后要不要"的问题，不是"现在必须" |
| 首屏图标 | 全部上云存储 | 15 张 webp 仅 **202 KB** | **改为进包**——首屏是包内读，发到 CDN 只会多一次往返。上云的是 history 那 34.7 MB 大图 |
| tabBar 图标 | 沿用站点 SVG | 小程序 **不支持 SVG** | 用 `tools/make_miniapp_tabbar.py` 以 PIL 按设计令牌重绘 PNG |

另外两处平台约束已在 §4.1 记录（**tabBar 页面必须在主包**、**switchTab 不能带参数**），
它们直接改变了页面分层，属于设计期就该知道的事。其中「switchTab 不能带参数」在
「门户 → 词典」传关键词时变成了实际障碍，解法（一次性信箱）也记在 §4.1。

> ★ **一次学费（值得跨项目记住）**：门户页 `navigateTo('/pages/scientist/index')`
> 指向一个**没写进 `app.json` 的页面**，点下去就是死链 —— 而当时的校验器 20 项全过。
> 因为它只做**正向**检查（app.json 里的页面文件是否齐全），没做**反向**检查
> （代码里跳转的目标是否登记过）。**方向反了，这类错就永远看不见。**
> 现在补了 4 条反向判据（跳转目标已登记 / switchTab 只能跳 tab / navigateTo 不能跳 tab /
> require 可解析），并配了变异自证脚本证明它们真的拦得住。
> 结论：**护栏写完必须自证 —— 注入一个人造错误，看它报不报。**

## 1. 合规基线（它决定后面所有技术选择）

### 1.1 个人主体能力边界

| 能力 | 个人主体 | 对本站的影响 |
|---|---|---|
| 图文内容展示 | ✅ | 15 位科学家的正文、时间轴、术语，全部可做 |
| 教育信息展示 | ✅ 可用，但**不该选** | 教育类下唯一开放给个人的子类目；选中它会让成长计划资格失效（见下方 ★） |
| 信息查询 / 工具 | ✅ | **主类目就选它**：术语词典、知识自测、时间轴检索都归到这里 |
| 信息收集表单 | ⚠️ 仅**开发者可见**的单向反馈 | 可做「意见反馈」，**不可做公开留言** |
| **虚拟支付**（会员订阅 / 功能解锁 / 额度包） | ✅ **2026-08-31 起个人主体开放** | 条件：身份证 + **工具类目** + 认证备案；月限额 **10 万元**；费率 Android 1% / iOS 12%（腾讯 5% 限时免收）；前端 `wx.requestVirtualPayment`。★ 商品**仅限工具类目内的虚拟商品** → 变现必须是"工具型"，**不是卖课** |
| 微信支付（实物交易 / 资金结算） | ❌ | 卖实物、对公结算仍不可用（个人无营业执照） |
| 教育视频播放 / 直播 / 课程销售 | ❌ | **不放视频**；文案禁「课程 / 直播 / 报名」 |
| 深度合成（AI 问答 / AI 生成） | ❌ | 不做 AI 功能。想要 AI 只能等企业主体 |
| 公开社交互动（社区 / 论坛 / 笔记 / 评论） | ❌ 类目未对个人开放 | **不做公开排行榜**（展示他人昵称头像有被判 UGC 的风险） |
| getPhoneNumber（手机号） | ❌ | 不做手机号登录，静默 openid 足够 |
| 微信登录 / 云开发 | ✅ | 账号体系走这里 |
| 分享给好友 / 朋友圈 | ✅ | 增长主引擎 |
| 流量主广告 | ⚠️ 需后台实测确认 | 门槛 UV ≥ 1000，且个人主体广告位受限 |

> ★ **类目—成长计划冲突（v1.1 修正，推翻 v1.0 的"主选教育"）**
>
> 成长计划（2026 全年，入口在 mp 后台「行业能力 → AI 小程序成长计划」）明文要求：
> **「小程序类目仅包含文娱、工具、社交、深度合成、资讯虚拟行业类目」** —— 教育**不在其中**。
> 即选中「教育 > 教育信息展示」后，后台「参与计划」按钮很可能置灰，
> 代价是**失去 6 个月免费个人版云环境**（新账号拿不到免费体验名额时，这是最省钱的路径）。
>
> **决策：平台类目只报「工具 > 信息查询」**，把小程序定位成"科学家知识查询工具"。
> 这不是硬凑——398 条术语的名称、分类、一句话释义全部可检索，再按科学家 / 分类 / 学科筛选，
> 就是实打实的信息查询功能。
> ⚠️ **但别把"按年份查时间轴"写进类目说明或简介**：数据层目前还没有 timeline（见 §4.1 末尾），
> 那是站点端的能力，小程序要等抽取器补上才敢承诺。
>
> ★ **工具类目还是虚拟支付的门槛**：个人主体开通虚拟支付的条件是「身份证 + **工具类目** + 认证备案」。
> 类目选错，丢的不止 6 个月云环境，还有整条变现通道 —— 这是"只报工具"的第二个硬理由。
>
> ⚠️ **但要用对工具类的边界**：「内容资讯分发」不在工具类范围内（电商 / 社交 / 外卖 / 出行 / 游戏同理）。
> 本站形态是科普阅读，**必须把"查询"做成主入口与主框架**——搜索框是首屏视觉重心，
> 结果区优先于浏览区，阅读只是查询结果的延伸。**v1 已按此落地**（见 §4.1 末尾）。
> 这是信息架构约束，不是措辞问题：审核员看首页若觉得是"看文章的地方"，
> 就判**功能与类目不符**，改文案糊不过去。
>
> **「教育」这个词要在名称、类目、简介里全程避开**：它同时是备案的**前置审批关键词**，
> 个人主体名称含「教育 / 培训」会在备案入口被直接拦下（详见附录 A）。
>
> ⚠️ 若审核以"内容与类目不符"驳回、必须补教育类目，**要在已领取成长计划权益之后再加**——顺序不能反。

### 1.2 三处必须纠正的认知

1. **「用云开发就不用备案」——错的。**
   混淆了两个东西：
   - **小程序备案**（在 mp.weixin.qq.com 后台做）→ **所有小程序无条件必须**，2023-09-01 起未备案不得上架。
   - **域名 / 服务器 ICP 备案** → 只有当你有自己的域名和服务器才需要。
   用云开发的正确收益是**省掉了第二条**，不是第一条。凡是宣传"云开发免备案"的，说的是域名那条。
2. **「个人主体做不了账号体系」——错的。**
   `wx.login` → 云函数拿 openid，立刻就有稳定用户 ID，无需任何授权弹窗、无隐私风险。收藏、进度、打卡、成长值全都能做。用户之间互相看不见，天然合规。
3. **「分享解锁内容」——是红线，会被封。**
   微信明令禁止诱导分享（分享才能看 / 分享才能解锁 / 集赞）。分享必须做成**用户自愿、分享物本身有价值**（如"我读完了牛顿的一生"成绩海报）。

### 1.3 现有文案扫描结果（已实测）

对 135 个页面全文扫描 `课程|培训|辅导|报名|学费|收费|资料包|购买|兑换|会员|订阅|直播|题库|答疑|一对一`，**仅命中 4 处，且 3 处是历史叙述，无害**：

| 位置 | 原文 | 处置 |
|---|---|---|
| `newton/detail/gravity.html:118` | "看火箭发射**直播**" | ⚠️ **建议改**「看火箭发射实况」——机审可能命中"直播" |
| `newton/timeline.html:110` | "换取**学费**" | ✅ 历史叙述，保留 |
| `curie/detail/xray.html:56` | "她**培训**人员" | ✅ 史实叙述，保留 |
| `newton/prototype/framework.html` | 早期框架稿 | ✅ 不迁移，忽略 |

> 结论：**文案风险极低，只需改 1 个词**。这是这个项目最大的运气——内容天然合规。

## 2. 总体架构

```
┌─ 小程序端（原生，分包） ────────────────────────────────┐
│  主包 <2MB : 门户 / 术语词典 / 我的                    │
│  分包 scientist <2MB : 15 位科学家的全部内容 JSON       │
│  分包 labs     <2MB : 15 种 Canvas 实验                │
│  分包 quiz     <2MB : 自测 + 成绩海报                  │
└────────────────────────────────────────────────────────┘
         │ wx.cloud（免鉴权，无需配域名白名单）
         ▼
┌─ 微信云开发 ────────────────────────────────────────────┐
│  云函数 login / syncProgress / submitQuiz / feedback    │
│  云数据库 users / progress / checkins / quizRecords     │
│  云存储 584 张图（原图 + 两档缩略图），CDN 分发          │
└────────────────────────────────────────────────────────┘
```

**为什么这套组合最快**：不需要买域名、不需要买服务器、不需要做域名备案、不需要配 request 合法域名、不需要自建鉴权与 token 流转。云函数内 `cloud.getWXContext()` 直接拿可信 openid。个人主体的可行路径里，这是唯一"零基础设施"的。

## 3. 内容迁移：不搬 HTML，搬数据

### 3.1 为什么不能搬

小程序没有 DOM，135 个静态 HTML **无法直接复用**。天真的做法是"手工重写 135 页"——那是 2 个月的工作量，且以后每加一位科学家就要再写 9 页。

### 3.2 中间内容层（关键架构杠杆）

现有资产里已经藏着**结构化数据**，比 HTML 值钱得多：

| 现有资产 | 实际是什么 | 小程序的角色 |
|---|---|---|
| `scientists/*/assets/js/terms.js` | **398 条术语**（`name/short/plain/analogy/extra/page/anchor/related/cat`） | 术语词典的**直接数据源**，零改造 |
| `tools/spec_<id>.py/.json`（12 份） | 每位科学家的**内容提纲**（正文段落、页面结构） | 正文数据源 |
| `scientists/*/timeline.html` 的 `data-year` 节点 | **时间轴事件**（年份 + 事件文本） | 时间轴页面数据源 |
| `tools/lab_templates.py` | 15 种 Canvas 实验的 **kind + 参数 + readout 模板** | 实验室数据源 |
| 169 张 history 照片 + `CREDITS.json` | 来源与授权 | 图片来源标注 |

**数据量实测（决定打包策略的关键）**：

| 项目 | 体积 | 结论 |
|---|---|---|
| 术语库 15 份 terms.js | **224 KB** | 极轻，**可整包内置** |
| 135 页正文抽成纯文本 | ≈ 700 KB–1 MB | 放独立分包，仍宽裕 |
| 内容 JSON 合计 | **≈ 1 MB** | 单分包 2MB 上限内，**一次装下 15 位科学家** |
| 图片 584 个文件 | **34.7 MB** | 绝不进包 → 云存储 |

> 换句话说：**把 15 位科学家全部内容做成数据，占用不到 1MB**，而图片是它的 34 倍。资源策略比内容策略重要得多。

### 3.3 抽取器（要新建的唯一工具）

```
tools/export_miniapp_content.py
  输入：spec_*.py/.json + */assets/js/terms.js + */timeline.html + lab_templates.py
  输出：miniapp/data/scientists.js   15 位元数据（id/名/生卒/学科/一句话/主题色）
        miniapp/data/terms.js       398 条术语（按科学家分键）
        miniapp/data/content.js     每位科学家：index/timeline/about/detail[] 正文
        miniapp/data/labs.js        15 个实验：kind/参数/readout 文案
        miniapp/data/credits.js     图片署名（Wikimedia PD/CC）
```

**硬约定**（沿用静态站的坑位经验）：
- 抽取器必须**幂等**，重复跑结果逐字节一致（便于 CI 校验）。
- 保留 `anchor` 与 `data-page-node-id`：术语弹窗跳转靠它。
- 图片路径重写为云存储 URL，**不保留相对路径**。
- 抽取后做一次**反向断言**：398 条术语、135 页、15 位科学家三个计数必须与静态站一致，不一致就报错退出（防静默丢内容）。

### 3.4 资源三级处置

| 级别 | 内容 | 处置 |
|---|---|---|
| 进包（< 200KB） | tabBar 图标（**必须 PNG，tabBar 不支持 SVG**）、启动图、少量 UI 图标 | 转 PNG，2x/3x |
| 云存储 + CDN | 169 张历史照片 + 自绘 SVG（348 个）+ 缩略图 | 生成 **thumb 400px / full 1200px** 两档；列表用 thumb，详情用 full |
| 不迁移 | `prototype/` 早期稿、`shots/` 验证产物 | 丢弃 |

**SVG 单独说明**：小程序 `image` 组件**支持** SVG，但有三个已知约束——① 不支持百分比单位；② 不支持 element 通用属性；③ 社区反馈 base64 内联 SVG 存在 iOS/Android 版本碎片化。因此：
- 站内自绘线稿（348 个）**不要 base64 内联**，做成**云存储 URL 外链**（`mode="widthFix"`）；
- 每个 SVG 必须**显式写死 width/height**，并把 `viewBox` 检查一遍（viewBox 错会变形，这是高频坑）；
- 保留一份 PNG 兜底，线上发现不渲染可即时切换。

图片压缩用现成的 Pillow 能力（`/Users/shuwei/.workbuddy/binaries/python/envs/default/bin/python`，裸 python3 无 PIL），思路直接复用 `make_homepage_icons.py`。

### 3.5 Canvas 实验移植（可复用度 ≈ 90%）

15 种实验（orbit/pendulum/projectile/wave/graph/atom/growth/field/ellipse/branching/periodic/turing/blackhole/induction/pathintegral）的**绘制函数体几乎可以原样搬**，只需替换 3 个入口：

| 浏览器写法 | 小程序 Canvas 2D 写法 |
|---|---|
| `canvas.getContext('2d')` | `wx.createSelectorQuery().select('#c').fields({node:true,size:true})` 拿 `node` 再 `node.getContext('2d')` |
| `requestAnimationFrame(fn)` | `canvas.requestAnimationFrame(fn)`（`window` 不存在） |
| 用 CSS 控制画布尺寸 | 必须 `canvas.width = w * dpr; canvas.height = h * dpr; ctx.scale(dpr, dpr)` |

**兼容性坑（移植时逐个验证）**：小程序 Canvas 2D **不支持 `Path2D`（部分版本）/ `ctx.filter` / `document`**；`ctx.transform` 需手工算矩阵。静态站历史上踩过的三个物理坑（全反射、循环步长零守卫、坐标奇点）**会原样复现**，直接沿用已有修复。

沿用静态站的 e2e 判据：**拖首个滑块必须让读数文本变化**；`draw(ts)` 必须 `if(typeof ts!=="number") ts=Date.now()`（首帧时间戳为空）。

## 4. 路由与分包

### 4.1 tabBar（4 项，全部 PNG 图标）

| 位置 | 页面 | 对应现有站点 |
|---|---|---|
| 读懂 | 门户首页 · **查询优先**（搜索框 → 跨库结果 → 图标桌面） | 根 `index.html` |
| 词典 | 术语检索（398 条，分类筛选） | `glossary.html` |
| 实验室 | 玩一玩（15 种 Canvas） | `labs.html` |
| 我的 | 学习档案 / 打卡 / 自测记录 | `about.html` 的延伸 |

> ⚠️ **硬约束（v1 落地时实测确认）：tabBar 的页面必须在主包。**
> 所以「实验室」不能直接把分包里的 canvas 页挂上 tab，只能拆成
> **主包入口页（列表/说明）＋ 分包实验页**。v1 先上 3 个 tab（读懂 / 词典 / 我的），
> 等 Canvas 移植完成再加回第 4 个。
>
> ⚠️ **`wx.switchTab` 不能带 query 参数**。所以「门户点科学家看详情」必须走
> `wx.navigateTo` → `pages/scientist/index?id=xxx`（v1 已按此落地）。
> 反过来，门户要把关键词交给词典页（同为 tab）**只能走一次性信箱**：
> `store.setPendingQuery(q)` → `wx.switchTab` → 词典页 `onShow` 取走即清。
>
> ★ **首页的查询优先结构（v1 已落地，★ 过审约束）**
>
> 首屏顺序固定为：**搜索框（深色区里唯一的白色块＝视觉重心）→ 结果区 → 浏览区**，
> 术语结果排在科学家前面（查询工具的主产出是词条）。三条实现纪律：
>
> 1. **检索逻辑只有一份**（`utils/search.js`），门户与词典共用。排序权重：
>    名称完全匹配 → 名称前缀 → 名称包含 → 分类 → 一句话释义 → 科学家名。
>    同一个词在两处给出不同结果，用户会以为数据不一致（站点端踩过这个坑）。
> 2. **跨 tab 传词用一次性信箱**，且词典页接手时**要一并清掉旧筛选**——
>    否则词带过去了却被上一次的筛选挡住，看着像"查不到"。
> 3. **索引里的检索字段（`_n/_c/_s/_p`）绝不进 setData**：它们只用于内存排序，
>    推过桥的必须是剥离后的纯展示字段。
>
> ⚠️ **数据层缺口（会变成对外承诺问题）**：`miniapp/data/` 目前只有
> `roster.js` + `terms.js`，**没有 timeline**。所以首页快捷查询只放有数据支撑的维度
> （热门词 / 学科 / 分类），**"按年份查"要等抽取器补 timeline**。
> 别在类目说明、简介或页面文案里承诺它。

## 5. 数据模型（云数据库）

```
users        _id(=openid), nickName, avatarUrl, createdAt, lastActiveAt,
             inviteFrom, totalTerms, streakDays, badges[]
progress     _id, openid, scientistId, pagesRead[], termsMastered[],
             lastReadAt, pct
checkins     _id(=openid_yymmdd), openid, date, createdAt
quizRecords  _id, openid, quizId, scientistId, score, createdAt
feedback     _id, openid, content, createdAt      ← 仅开发者可见
```

**权限规则（关键，写错就是数据泄露）**：`progress` / `checkins` / `quizRecords` 一律设为**「仅创建者可读写」**——这样即使前端逻辑有漏洞，也读不到别人的数据。`users` 只允许创建者读、云函数写。**任何集合都不设「所有人可读」**。

**索引**：`progress` 建 `openid + scientistId` 复合索引；`quizRecords` 建 `openid + createdAt`。

内容（术语 / 正文 / 实验参数）**不进云数据库**——它们是只读静态数据，打包进分包即可，既不耗云调用次数，也不怕冷启动。

## 6. 账号与隐私合规

**登录时序（全程无弹窗）**
```
小程序启动 → wx.login() 拿 code → 云函数 login(code)
  → cloud.getWXContext() 得 openid → 查 users 集合
  → 无则建档，有则更新 lastActiveAt → 返回用户档案
```
昵称头像用**「头像昵称填写能力」**（用户主动点击才填，**不做强制授权**）。个人主体拿不到手机号，也不该要。

**必须配置项（漏了会被驳回）**
- 后台填写《小程序用户隐私保护指引》：声明收集 openid、昵称、头像，及用途。
- 首次调用隐私接口前弹**隐私授权弹窗**（官方组件，不要自己画）。
- 「我的」页放**隐私政策 + 用户协议**入口（个人主体也要有）。

## 8. 增长设计（全部在合规线内）

个人主体做不了 UGC 和公开榜，但增长引擎**够用**——这个内容天然适合"读完想告诉别人"。

1. **成绩海报（主力）**：读完一位科学家 → Canvas 生成"我读完牛顿的一生"卡片（生卒年 + 3 个关键词 + 二维码）→ 保存相册 / 分享给好友。完全复用现有 `make_share_card.py` 的排版思路。**注意：是用户自愿分享，不是分享才能看。**
2. **术语自测**：398 条术语抽 10 道题，答完出分 → 海报。自测结果是用户自己的数据，不公开展示、不做榜。
3. **连续打卡 + 成就徽章**：只在「我的」里对自己展示。徽章命名贴合内容（如「读完《自然哲学的数学原理》」）。
4. **邀请关系**：`onShareAppMessage` 带 `inviteFrom` 参数，仅在云端记录关系、用于你自己的增长分析，**前端不展示他人**。
5. **公域流量 + 免费后端**：报名微信「AI 应用及线上工具小程序成长计划」（激励期 2026 全年）。**已核实**：入口在 mp 后台「行业能力 → AI 小程序成长计划」，**个人主体可参与**，且**不要求小程序具备 AI 能力**（所以别为拿资源而加 AI 功能，那会触发深度合成类目）。硬条件是**「类目仅含文娱 / 工具 / 社交 / 深度合成 / 资讯」**——这就是我们不选教育类目的原因。权益：**免费 6 个月个人版云环境**、We 分析专业版、专属曝光入口。
   ★ **领取时机是注册后立刻，不是上线后** —— 开发本身就需要云环境；「上线后 15 天到期」指的是非成长计划路径的免费环境。
6. **流量主广告**：UV ≥ 1000 后可申请。定位为"覆盖云开发月费"即可，别为广告牺牲阅读体验。

7. **变现（一期就能做，别排到二期）**：虚拟支付已对个人主体开放（月限额 10 万）→ 只做**工具型虚拟商品**：
   会员订阅（去广告 + 全部科学家深度解析）、功能解锁（成绩海报高级模板、自测题库扩展）、查询额度包。
   **不做**「卖课 / 卖资料包」——踩教育类目与个人主体红线。**付费墙不得挡住核心内容**：必须能免费读完全部 15 位，
   付费只买"更好的形式"。这把尺子同时保过审与保口碑。

**红线复述**：不诱导分享、不做公开榜、不展示他人 UGC、不做分享解锁。

## 附录 B · 本目录与静态站的关系

- `miniapp/` 与现有静态站**互不影响**：静态站的发布上传的是项目根目录，会**顺带带上** `miniapp/` 的文本文件（无害，仅占少量体积）。若后期小程序代码变大需彻底隔离，可把 `miniapp/` 独立成仓（`../读懂牛顿-小程序/`）。
- 内容以**单向同步**为原则：静态站是内容源，小程序是消费端。改动内容 → 重跑 `tools/export_miniapp_content.py` → 小程序发版。**不要让小程序反向改静态站**。
- 注意：发布静态站时**不要**把小程序源码当作站点内容上传；`miniapp/` 内不放任何会被静态站引用的路径。
